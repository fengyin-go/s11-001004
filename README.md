# 智能采集调度平台

面向多源网页采集、增量抓取、自动化流程编排、采集结果校验与失败重试的智能数据采集调度平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 批次水位提交工作区

增量采集页内置「批次水位提交工作区」，采集存储页可打开每张配置收到的批次收据。
它演示一条严格的投递语义：**记录先落库、水位后推进，写入受阻时游标绝不移动**。

### 原子边界

一次「确认投递」在 `BatchCommitService` 的同一把进程锁内完成四步，对外是一个原子事务：

1. **身份核对**：以「来源 + 批次号」定位批次；批次号重用但内容或存储目标改变直接拒绝；
2. **水位 CAS 检查**：来源当前水位必须仍等于批次登记的旧水位，
   两个批次争用同一旧水位时，先提交者推走水位，后提交者收到 `WATERMARK_CONFLICT`；
3. **记录落库**：本地存储替身把记录真实写成 JSONL（临时文件 + `fsync` + 原子替换），
   写入带幂等键，网络中断后再次确认复用原文件，不会再写一份；
4. **推进游标**：只有第 3 步确认成功，才把来源水位推进到新水位并开具收据。

任何一步失败都在锁内返回，水位结构性保留；收据永久保留当次水位与存储目标。

### 本地存储替身与故障演示

`backend/app/services/local_sink.py` 用本地文件系统模拟真实存储（文件在
`backend/var/sink/`，可直接打开核对，不是页面数字变化），并支持四种故障模式：

| 模式 | 行为 | 演示点 |
| --- | --- | --- |
| `normal` | 正常写入并返回收据 | 成功路径 |
| `deny` | 持续拒绝写入、不产生文件 | 写入受阻，水位留在原处，恢复后从失败步骤接着提交 |
| `lost_ack` | 记录已落盘但返回网络中断 | 再次确认复用原批次、原文件，不重复写 |
| `flaky` | 同批次首次失败、之后恢复 | 失败步骤可续投，尝试次数累计 |

页面上可直接切换故障模式、触发并发争用演示（两个线程用同一旧水位同时提交，
只允许一个成功）、重置工作区。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
